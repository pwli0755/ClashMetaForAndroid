# CMFA 内置 Tailscale

本改动仍在验收中，不能仅凭控制面在线判断手机应用可用。

## 使用

需要 Android 10 或更新版本。停止 CMFA 后，打开「设置 → Tailscale」，启用集成并设置设备名称；启动 VPN 后返回此页面，通过「浏览器登录」完成官方认证。状态页显示后端状态、分配的 IP，以及后端提供的设备登录到期日期。设备名称可在 VPN 运行时修改；旧测试名首次打开设置页时改为按手机型号生成的名称，不重新注册设备。「退出登录」调用真实后端 Logout；停止 VPN 或关闭集成保留登录数据。

继续使用原有 URL 订阅。原应用名单无需数据迁移：仅允许模式允许选中应用使用机场，排除模式允许未选中的应用使用机场，全部模式允许能够识别的已安装应用使用机场。共享 UID 的全部包必须都满足权限条件，未知来源直连。关闭集成恢复原 VPN 应用访问控制。

独立包名测试版无法直接读取正式版的 Android 私有数据。正式版与测试版的数据是独立的；正式版的数据不受测试版安装影响。

## 分流与配置

运行配置顺序：订阅原文 → 现有持久覆写 → 会话覆写 → CMFA 原有必要修正 → Tailscale 修正。只修改当前内核的内存配置，不把 RawConfig 重序列化写回订阅。内置实例独立于订阅的节点列表，不添加引用机场节点的组。

优先处理 Tailnet IPv4、IPv6、完整 .ts.net 域名，以及开启接受路由时后端返回的 PrimaryRoutes。其次，未获机场权限的来源直连；其余流量进入原订阅规则。集成模式固定使用规则模式。普通订阅规则中的国内直连和广告拒绝继续生效。

MagicDNS 查询在 hosts、fake-IP 和常规解析缓存之前交给内置实例，失败直接返回错误。普通公网名称保持原有 DNS 行为。不支持短主机名；应用自带的加密 DNS 不受 Android DNS 接管保证。为防止改写受保护目标，集成模式关闭嗅探；同时启用 IPv6、全路由与 DNS 接管，关闭 VPN 绕过和系统 HTTP 代理。关闭集成后读取原设置。

不接受默认出口路由，不把 RFC1918 全部送入 Tailnet。已知子网前缀持久保存在私有目录，撤销或断线期间拒绝外泄。子网与本地 LAN 重叠时优先 Tailnet。接受子网路由时，每个新流读取当前后端路由状态，以避免只靠定时刷新导致新路由遗漏。

认证和已知路由位于应用 files/clash/cmfa-tailnet，权限 0700；不会放入订阅或常规备份。认证链接仅由显式登录命令读取当前实例，并限制为官方 HTTPS 认证地址。实例的认证日志输出已关闭。

订阅先在 processing 中下载并校验，再通过候选目录和 previous 备份替换。运行配置解析失败不会调用 ApplyConfig；已经加载过配置时保留 VPN 和旧连接。首次启动配置错误仍会报告启动失败。

## 构建与维护

沿用上游 Gradle 构建，使用 MetaCubeX Go 1.26，并应用 .github/patch 下的 Go 补丁。Android NDK 版本由根构建文件指定。

core/mihomo-patches/tailnet.patch 保存最小内核扩展，core 配置阶段自动幂等应用。升级内核后如补丁不匹配，构建应失败并要求人工适配，不能静默忽略。

测试版 local.properties 使用独立 custom.application.id；此文件不提交。不要用不同签名覆盖正式安装，也不要卸载正式版来安装测试版。

### Android 16 真机

通过 UI 完成内置实例的官方网页登录并取得 IPv4/IPv6。以下请求均从真实 Edge 应用发出，同时核对 VPN 前台服务及进程，避免把 VPN 退出后的直连误算为通过。

- Edge 在允许名单内时：测试订阅的拒绝规则阻断 `example.com`；直连规则访问 `example.net` 返回 HTTPS 200；指定 HTTP 测试代理收到 `example.org:443` CONNECT，并成功转发 HTTPS 200。此项使用可观测测试代理；真实机场验证见后文。
- Edge 在允许名单外时：相同订阅要求拒绝的域名返回 HTTPS 200，要求代理的域名也直连成功，测试代理未收到新增 CONNECT。
- 允许名单内外的 Edge 均能访问用户提供的 Tailnet 完整域名，目标返回 HTTP 200，TLS 1.3，浏览器判定连接安全。订阅中针对 `.ts.net` 和 Tailnet IPv4 的拒绝规则不会抢先处理这些请求。
- 普通 URL 测试订阅从节点 A 更新为 B 后，源配置和组引用同步更新，独立运行快照切换，未写入 Tailscale 配置或认证信息。同一 VPN 进程下 Tailnet HTTPS 仍返回 200，无需重新登录。
- 无效 YAML 与 HTTP 404 更新均显示具体错误，原下载文件及当前运行快照的 SHA-256 不变，VPN 保留。
- 切换到故意损坏的测试配置时保留旧快照，并恢复原配置选择，避免界面与实际运行配置不一致。应用冷启动遇到损坏配置时能恢复最后成功快照；随后 Tailnet HTTPS 返回 200，无需重新登录。
- 蜂窝 → Wi-Fi → 蜂窝切换后分别取得 Tailnet HTTPS 200，VPN 进程保持不变。短暂断网时请求明确失败，VPN 进程存活。
- 停用集成并保持原 AcceptSelected 空名单后，Android VPN UID 范围恢复为应用自身（不含 Edge）；Edge 访问订阅要求拒绝的公网域名返回 HTTPS 200。重新启用后 Android 恢复全应用接管，认证保留。

### 真实机场订阅补充

用户在独立测试版中导入并启用了普通 URL 机场订阅（46 个节点）。未记录订阅地址或凭据。

- 允许名单为空时，Edge 的普通 HTTPS 与 Tailnet HTTPS 均返回 200。结束前再次复测，日志确认 `example.com` 走 DIRECT，8000 端口走内置 Tailscale，两者返回 200；认证保留。
- 临时将 Edge 加入允许名单后，内核日志确认 Google 匹配原订阅机场策略、百度匹配原订阅 DIRECT。Edge 分别取得 Google HTTPS 204、百度 HTTPS 200；同一 VPN 进程下 Tailnet HTTPS 返回 200。
- 从现有配置列表手动更新真实 URL 订阅，UI 报告成功，源配置字节与运行快照均发生变化，更新后仍为 46 个节点。源配置未写入应用管理的 Tailscale 节点或状态目录，允许名单保留，无需重新登录；更新后重复上述机场、直连和 Tailnet 请求仍成功，VPN 进程不变。
- 用户另提供了同一 Tailnet 设备的 8000 端口，明确使用 HTTP。Edge 访问返回 HTTP 200，内核日志显示 `CMFA-INTERNAL-TAILSCALE-v1`；按 HTTPS 访问时的协议错误不计为故障。

8000 端口地址解析到 Tailnet 设备本身，不能替代“访问通过已批准子网路由转发的局域网地址”验收。当前未开启接受子网路由，尚未取得可测试的局域网服务地址。测试结束恢复原允许名单，保留用户新导入并启用的真实订阅。

### 已修复问题

订阅拒绝路径的两个 `WriteBuffer` 实现未释放所接管的缓冲区，debug 内核因此触发 `panic: leaking buffer`。已补齐释放，并加入 `TestRejectWritersReleaseOwnedBuffers`；debug 标签回归测试通过，真机拒绝与代理对照期间进程未退出。修复与测试包含在 `core/mihomo-patches/tailnet.patch`。

Tailscale 后端等待 VPN socket 保护就绪后启动；关闭 VPN 时先暂停后端。运行配置使用独立文件快照，订阅更新不改动正在运行的文件。失败切换恢复原配置选择，配置列表监听加载结果刷新。
